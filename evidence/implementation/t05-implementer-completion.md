## Implemented behavior

- Disabled-default configured Google authorization-code login on same-origin /api/auth, exact allowlisted verified identities, Secure/HttpOnly/host-scoped/SameSite=Lax cookies, D1 session lookup, actual logout and no-store responses.
- Library-owned PKCE and signed/state-cookie correlation; fixed provider extension requires the library's persisted nonce, public Google verifier RS256/JWKS/issuer/audience/age checks, explicit future expiry and bounded verified identity before mapping. Caller ID tokens, additional scopes, provider parameters and arbitrary callback destinations are rejected. Google login uses only openid/email/profile, online access, no granted-scope union, and account selection. All identity linking disabled.
- Login token fields discarded before account create/update storage; account cookies disabled; no token, raw provider error, IP or user agent in public session/profile projections. Current trusted TenantContext is constructed only after signed live session, allowlist and active-profile checks. No request ID/header/body user ID can select a tenant.
- Strict 4096-byte JSON boundaries and exact mutation Origin checks. /api/me safe shared-schema projection; preferences compare-and-swap with active tenant predicate and expected version; invalid/stale/cross-origin requests denied. Safe /api/auth/get-session returns user plus session id/creation/expiry only, never bearer token.
- Login creates profile only; no mailbox, storage, consent, import, scheduling or model side effects. Reporting preferences do not rebuild FX: response explicitly states valuation not configured (T19 future boundary).
- SHA-256 login-state identifiers through the public library storage policy; AES-256-GCM bounded verification values with fresh nonces and purpose/origin/identifier AAD, using Web Crypto HKDF from AUTH_SECRET. No plaintext PKCE/nonce/raw OAuth state at rest, no fabricated pre-login tenant. The public DBAdapter extension preserves read/update/consume/delete and D1 passthrough transaction semantics.
- Request-local new-user compensation after profile or account creation failure: callback factory is per request; its callback entry point is one-shot, and IDs are captured at successful DBAdapter.create before queued after hooks. Cleanup can delete only newly created users with no account and no session, preventing email-link recovery or profile resurrection during deletion. A whole-database outage during cleanup still needs operator reconciliation; no unsafe session access is granted.
- Private API fallback denies unauthenticated requests with 401 and returns explicit not-implemented for authenticated callers. Public health/config routes remain parent-composed before this router. Public config/UI login stay disabled until reviewed operator setup.
