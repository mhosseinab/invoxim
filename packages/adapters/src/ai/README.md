# Bounded AI adapters

## Configuration

Inference is disabled by default. `aiConfiguration` returns a configuration only when `AI_ENABLED=true` and all of these validate: `AI_REGISTRY_JSON` (at most 32768 characters), `CREDENTIAL_KEYRING`, `AI_BUDGET_JSON` (at most 4096), an enabled `AI_CLASSIFICATION_JSON` (at most 4096; `AI_CLASSIFICATION_ENABLED=false` disables it) and the configured classification provider's own credential: a Workers AI `AI` binding with `run` for `cloudflare-clef` (also when `provider` is absent), or a usable `PERPLEXITY_API_KEY` secret for `perplexity-decider`. Without the classifier configuration and that credential the whole AI configuration is `null`; one provider's credential never satisfies the other. There is no funded default or presumed free model. Hosted inference is optional but all-or-none: `AI_HOSTED_DESTINATION`, `AI_HOSTED_MODEL` and `AI_HOSTED_KEY` must all name a registry entry and model, or all be absent. BYOK is written through the authenticated settings API and encrypted with the existing tenant/primary/byok-key cipher binding. Optional LangSmith tracing (`AI_TRACING_ENABLED`) never disables processing when invalid, redacts secrets, and includes content only for the synthetic probe when `AI_TRACING_INCLUDE_CONTENT=true`.

Registry entries select exact HTTPS endpoints and approved model IDs, text protocol capabilities, input/output/time limits, policy notice references and explicit approved USD-micro price metadata with source/date/version. `pricing.ts` is the one pricing snapshot shape for registry models, receipt classification and budget verification (A5). User requests cannot supply endpoints, headers, tools, files, images or native PDFs. Unknown/invalid price or budget configuration disables inference. Zero hosted monetary allowance is valid; BYOK still consumes the application's document/unit limits.

Operator configuration revisions are immutable by contract. Increment `configVersion` and the relevant `policyVersion` when changing endpoint, model/processor, capability, privacy policy, price or limit information; increment the configuration revision on hosted credential rotation. Existing settings are not an undisclosed consent to another destination. No registry history service is implemented.

## Receipt classification (AI-CLASSIFIER-PROVIDER)

`decision-protocol.ts` is the provider-neutral protocol: the fixed `receipt` (noul), `documentType` and `category` (choice) questions, strict answer validation against the models the selected transport may echo, the 0.1/0.9 thresholds and document routing (`document-type-classification-v4`). `decision-classifier.ts` turns it into the core `EmailClassifier` over a small `DecisionTransport` port. Transports:

- `clef.ts`: Workers AI binding `run("@cf/cloudflare/clef", {model:"clef",...})`; deadline/throw is `outage`, caller abort is `timeout` (unchanged). `clef-protocol.ts` is a Clef-named facade.
- `perplexity-decider.ts`: fixed `POST https://api.perplexity.ai/v1/decisions`, `Authorization: Bearer <PERPLEXITY_API_KEY>`, body exactly `{model, state, questions}`, `redirect: "manual"`, 64 KiB bounded body via `src/http.ts`, deadline/abort race. Status mapping before any body read: 401 `invalid-key`; 403 `unsupported`; 429 `rate-limit` with `parseRetryAfter` (30 s default); 400/404/405/413/422 `unsupported`; 3xx/5xx/other `outage`; unreadable or oversized 2xx body `outage`; deadline/abort `timeout`. Invalid decision JSON or a different echoed model is `needs-review/schema`. No retry inside the adapter. Classification failure handling (security reviews 2026-10-15): 401/403/429 are rejected before processing and settle as zero known usage, releasing the reservation. Only 401 is `invalid-key` and sets a shared 15-minute operator-key cooldown; 403 (which an edge layer may return for one request) is a per-document reviewable `classification-unsupported` outcome with no cooldown. A 429 or 401 is never persisted as a classification result: the engine returns a deferred outcome and the job is rescheduled through the job store's bounded retry path (`retry_wait`, `dispatch_at` at the Retry-After or cooldown end, outcome `transient`), never a budget pause. A lease that finds an active provider cooldown is likewise rescheduled for its end without calling. A slot used only by a zero-cost rejection is re-armed once its cooldown passes, so rejections never strand a document; billed calls stay at most two per document (the two attempt slots). Rejection retries are bounded by `JOBS_MAX_ATTEMPTS`: on the final lease a rejection becomes a reviewable `classification-invalid-key` or `classification-rate-limit` outcome. The usage settlement and the classification result are written in one D1 batch, so a crash cannot leave a billed attempt without its result for a later lease to pay for again. Outages and timeouts remain possibly billed, persisted and final for the document. The classification meter admits only the configured provider's destination/model. Logs: destination, status and a UUID `x-request-id` only.

`classification-config.ts` is a Zod union on `provider` (`cloudflare-clef`, optional for back-compat, or `perplexity-decider`) with literal model ids and input-only pricing; endpoints are not configurable. `classification-transport.ts` is the single readiness rule used by `aiConfiguration`, the pipeline runtime and `classifier-factory.ts`. The factory records the transport's destination id and the configured model on `ApprovedAiConfig`, the price snapshot and the classification configuration digest, so a provider or model switch changes the fingerprint and the reviewed onboarding digest (`onboarding/configuration.ts` selects the per-provider processor notice). The Perplexity notice follows Perplexity's [Privacy & Security](https://docs.perplexity.ai/docs/resources/privacy-security) page: general API terms say customer content is not used to train generative AI models; zero data retention is not on by default, so Perplexity or its model providers may retain request content; it claims neither zero data retention nor Decisions-specific terms. Usage is metered from `usage.input_tokens` under the existing classification reservation. Tests mock `fetch`; no live Perplexity call, latency or calibration has been verified.

## Fingerprints

Attempt and probe fingerprints hash the actual selected public configuration digest, settings revision/generation/credential version, accepted policy, consent, prompt version and classification flag, so a cache identity never depends only on a mutable version label. One tuple builder, `buildFingerprintTuple` in `configuration.ts` (AI-4), feeds `computeAiFingerprint`, `computeClassificationFingerprint` (`classifier-factory.ts`) and `computeRunFingerprint` (`budget-helpers.ts`). `test/ai-fingerprint.test.ts` checks that the three agree (AI-2) and pins literal 64-hex golden vectors for hosted extraction, BYOK extraction and classification, computed from the independent recipes before AI-4, so stored fingerprints stay byte-identical.

## Chat Completions transport (`http.ts`)

The adapter sends inert text parts, a fixed versioned extraction prompt, the configured output-limit parameter, and JSON schema/object format only when configured, through LangChain's `ChatOpenAICompletions` with a code-owned fetch that accepts only `POST <origin>/chat/completions`, zero retries and private callbacks. The actual request uses `redirect: "manual"`. It sends no tools or auxiliary file/network controls. Parts support the core's 64-part/100-character ID bounds. The upper reservation is the larger UTF-8 serialized request (normal or repair, including prompt/schema), plus the selected maximum output tokens and 1024 framing units; the extractor refuses an insufficient reservation before transport. Completion tokens include reported reasoning tokens for this protocol, so they are not counted twice. Other billing protocols need a separate verified adapter. Reported inconsistent/missing usage remains uncertain, and possibly billed failures retain conservative reservations.

Response bodies are read with the shared `src/http.ts` reader (AI-6): the configured `maxOutputBytes` cap and the abort/deadline race at the destination timeout. Status is mapped before any body read: 401/403 is `invalid-key`; 429 is `rate-limit` with `parseRetryAfter` or a 30 s default; 400/404/422 is `unsupported`; any other non-2xx, including 3xx, is `outage`; abort or deadline is `timeout`. Refusal, truncated finish and malformed protocol become safe typed results without raw provider text or secrets. A rate-limit floor is reported to the shared durable budget store, which blocks the same tenant/destination/model across changed extraction versions; a delay over one day is stored as an indefinite cooldown that requires manual recovery. The adapter never retries or changes destination itself.

## Budget and usage stores (AI-7)

`budget.ts` is a facade over `budget-types.ts`, `budget-helpers.ts`, `budget-meter.ts`, `budget-store.ts` and `budget-allowance.ts` (`readAiAllowance`). `createUsageStore({ db, owner, options, validate, wrap })` is the one usage-store factory: `owner` selects extraction-lease or synthetic-test-session admission, `validate` bounds persisted results, and `wrap` maps infrastructure failures. `createAiUsageStore`, `createClassificationUsageStore` and `createAiProbeUsageStore` are thin instances. Extraction and classification stores apply one attempt-ID rule: the claimed attempt ID must equal `runKey:attemptNumber` for the recomputed run key, otherwise reserve returns `budget`, authorize returns false and settle does nothing. Probes have no such claim.

## Settings and probe

Settings mutations require a recent verified session and exact origin. One conditional D1 batch revokes processing consent, fences pending jobs and pauses scheduling before the final settings CAS. A stale write cannot revoke fresh consent. GET projects shared strict masked DTOs and actual remaining application allowance; `configured` never means Start-ready, and `processingReviewRequired` is always true.

`POST /api/ai/test` accepts only the current settings version. It uses a fixed internal synthetic receipt, the selected extractor and the same quota transactions through explicit synthetic-test/session admission. It creates no source/document/job/purchase. A completed probe replays a bounded status; uncertain attempts stay sticky. Output, evidence, keys and global monetary limits are never returned. A synthetic passed probe establishes only this bounded fixture/protocol result, not live capability, general accuracy or model quality.

One Worker invocation database guard is shared across authentication, profile, vault, settings and probe operations, capped at 40 statements per request. No guard is reset inside an individual service.
