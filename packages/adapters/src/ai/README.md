# Bounded AI adapters

Inference is disabled by default. `AI_ENABLED=true` additionally requires a valid `AI_REGISTRY_JSON`, `AI_BUDGET_JSON` and existing `CREDENTIAL_KEYRING`. There is no funded default or presumed free model. Hosted credentials are server secrets selected by `AI_HOSTED_DESTINATION`, `AI_HOSTED_MODEL`, and `AI_HOSTED_KEY`; BYOK is written through the authenticated settings API and encrypted with the existing tenant/primary/byok-key cipher binding.

Registry entries select exact HTTPS endpoints and approved model IDs, text protocol capabilities, input/output/time limits, policy notice references and explicit approved USD-micro price metadata with source/date/version. User requests cannot supply endpoints, headers, tools, files, images or native PDFs. Unknown/invalid price or budget configuration disables inference. Zero hosted monetary allowance is valid; BYOK still consumes the application's document/unit limits.

Operator configuration revisions are immutable by contract. Increment `configVersion` and the relevant `policyVersion` when changing endpoint, model/processor, capability, privacy policy, price or limit information; increment the configuration revision on hosted credential rotation. Existing settings are not an undisclosed consent to another destination. Runtime attempt/probe fingerprints additionally hash the actual selected public configuration, settings revision/generation/credential version and accepted policy, preventing a cache identity from depending only on a mutable version label. No registry history service is implemented.

The Chat Completions adapter sends inert text parts, a fixed versioned extraction prompt, the supported output-limit parameter, and JSON schema/object format only when configured. It sends no tools or auxiliary file/network controls and follows no redirects. Parts support the core's 64-part/100-character ID bounds. The upper reservation is computed from the actual UTF-8 serialized request (including prompt/schema), the selected maximum output tokens and 1024 framing units; the extractor refuses an insufficient reservation before transport. Completion tokens include reported reasoning tokens for this protocol, so they are not counted twice. Other billing protocols need a separate verified adapter. Reported inconsistent/missing usage remains uncertain, and possibly billed failures retain conservative reservations.

Response bodies are streamed within byte/deadline bounds. Refusal, truncated finish, malformed protocol, unsupported model/fields, invalid credentials, rate limit and outage become safe typed results without raw provider text or secrets. A rate-limit floor is reported to the shared durable budget store, which blocks the same tenant/destination/model across changed extraction versions; overlong delays require manual recovery. The adapter never retries or changes destination itself.

Settings mutations require a recent verified session and exact origin. One conditional D1 batch revokes processing consent, fences pending jobs and pauses scheduling before the final settings CAS. A stale write cannot revoke fresh consent. GET projects shared strict masked DTOs and actual remaining application allowance; `configured` never means Start-ready, and `processingReviewRequired` stays true.

`POST /api/ai/test` accepts only the current settings version. It uses a fixed internal synthetic receipt, the selected extractor and the same quota transactions through explicit synthetic-test/session admission. It creates no source/document/job/purchase. A completed probe replays a bounded status; uncertain attempts stay sticky. Output, evidence, keys and global monetary limits are never returned. A synthetic passed probe establishes only this bounded fixture/protocol result, not live capability, general accuracy or model quality.

One Worker invocation database guard is shared across authentication, profile, vault, settings and probe operations, capped at 40 statements per request. No guard is reset inside an individual service.

Primary protocol references checked on 2026-10-12 (Context7 unavailable): [Chat Completions](https://developers.openai.com/api/reference/resources/chat), [Structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs). No live provider invocation or deployment is implied by intercepted HTTP fixtures.
