## Implemented behavior

Jobs persist in D1 before transport. The Worker now exposes fetch, scheduled and queue entry points in one composition root. Strict opaque job envelopes, bounded rotating tenant selection, atomic tenant/global lease limits, monotonic fences, generation/consent/profile guards and bounded retries protect durable work. A dispatcher reservation precedes queue sends; lost sends and expired leases recover from D1. Financial source commits already completed before a crash are recognized before acknowledgement, preventing duplicate spending. Terminal status plus a safe outcome is the durable issue. Missing processing handlers pause honestly instead of reporting success. Disabled queue acknowledgement does not complete/delete durable jobs; later dispatch repairs delivery.

An invocation-scoped private statement counter bounds job persistence at 24–40 statements (default 40), including each batch statement. Stage reservations preserve recovery, scheduling and delivery. Tenant cursors advance through processed work, preventing hot-prefix and budget-exhaustion starvation. Actual minimum 24 proof handles an expired exhausted lease, cancels stale generation work, and dispatches fresh work in the same invocation. This does not prove Free-plan CPU viability, throughput or costs. Future ingestion persistence must share remaining invocation capacity.

Gmail authorization is independent of Google login. Session-bound one-use state/PKCE, signed identity claims and bearer identity matching validate the authorized mailbox and actual read permission. Credentials stay encrypted; workspace A can own independently authorized B and C. New callbacks leave awaiting_import and make no discovery/message/parser/model call or processing job. Reconnect validates the expected account/version/generation, preserves omitted valid refresh tokens and preserves frozen consent/import facts. Resume requires an explicitly supplied current-consent validator; default behavior pauses existing processing. Mailbox limits are enforced atomically for new and reactivated connections.

Refresh acquires a D1 lease before provider HTTP and immediately checks current owner/fence/expiry, credential version, connection generation and active profile. Bounded transport ends before lease expiry; late outcomes cannot overwrite reconnect/disconnect state. Invalid grants pause only the affected connection, retaining records. Local disconnect clears credentials/fences work and retains imported records; it does not revoke a provider-wide grant or implement full account deletion. Callback redirects only to the fixed /onboarding/review seam with a safe outcome. The actual review/start UI remains T29.

Shared strict mailbox/sync Zod DTOs generate t07-t08-openapi.json. POST /connections/:id/sync requires a verified session, exact origin, owned connection and active processing authorization; awaiting_import is review_required. GET /connections returns bounded safe mailbox metadata with hasMore, never tokens/key references. Start requires recent authentication; disconnect uses expected revisions and supports exact replay.

External-service ports remain provider-neutral in core. Worker/adapters consume validated environment/Wrangler bindings; credentials/keyrings remain server secrets. Checked-in variables disable auth/Gmail/jobs. No vendor SDK/env reads entered core, arbitrary endpoint or silent provider fallback was added. Existing public/demo capability remains disabled for live sign-in/connection pending operator and UI readiness.
