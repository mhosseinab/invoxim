# Truthful product presentation and first use

1. Read `docs/13-presentation-and-onboarding.md` for user-facing work. Position purchase records, evidence, and useful outcomes; keep financial charts secondary. Do not redesign the scope into accounting or a chatbot.
2. A provider name in a roadmap is not an available feature. Public copy, buttons, and navigation must follow implemented/reviewed capabilities and operator readiness. Never invent customer counts, testimonials, security status, complete coverage, savings, prices, or a selected brand.
3. Login is not mailbox permission; a mailbox callback is not authorization to start scanning. Explicit review/start binds real mailbox, range, processing destinations, allowance, and hourly behavior. No unapproved content read or model call before that action.
4. Default history stays 12 months. Process the recent 30-day slice first; do not silently narrow coverage to achieve a speed target. Real records become available before the whole import completes. No fake percentages, ETA, zero-spend conclusions, or auto-redirect that steals focus.
5. Hosted inference is default only when approved/configured; BYOK is optional advanced setup. Drive is optional after first value or explicit request. Do not hide processing destinations to make onboarding shorter.
6. The example route is static, synthetic, and read-only. Never mix it with a tenant, private cache, exports, metrics, or live provider calls. Production cannot import testkit.
7. Paid/refunded/net values follow the ledger and supporting events. Invoices and pending refunds are not completed monetary events. Label lifecycle versus period values; do not count source documents as purchases.
8. Optional pilot measurement is off by default, requires separate opt-in, collects no receipt content or financial identifiers, and is not a product feature gate. Requested evidence access does not prove an external page was read.
9. Test keyboard/mobile, provider refusal, wrong account, refresh/two tabs, partial/no results, budget pause, disclosure changes, and unavailable originals. Review copy against actual DTOs, not just screenshots.
10. Report planned designs/tests as planned. Pilot targets and competitor assertions are not product-market fit. No added onboarding SaaS, analytics SDK, feature-flag service, or broad new architecture.
