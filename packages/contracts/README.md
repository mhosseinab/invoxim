# Shared bounded contracts

Strict Zod validators implement the three canonical designs in `/contracts`, tested against Ajv 2020-12 with date/URI formats and all supplied synthetic extraction/onboarding/config fixtures. Explicit schema expressions were generated once during implementation; there is no runtime interpreter or schema plugin engine. JSON designs remain the design authority. Known copy keys additionally use the central catalog; integers must fit Zod's safe integer range.

Extraction shape validity does not verify evidence grounding, currency support, monetary magnitude/precision, tax consistency or payment eligibility. Evidence quotes are transient. Never persist model responses or this entire transient extraction DTO. Later extraction tasks must validate actual identified input parts before classifying verified facts.

`startImportSchema` validates the bounded review shape: owned connection identity is a server check, never trusted merely because the identifier parses. Consent/disclosure revision, ownership, scopes, budgets, idempotency, frozen interval, and atomic run/schedule persistence belong to later use cases. No route, session authority, mailbox scan or scheduling behavior is implemented here. Processing disclosure exposes bounded destination/model/policy identifiers, separate conversion destination, nullable allowance and reset, actual account/range/preferences, and no endpoint/key.

`projectPublicConfig` parses nonsecret operator configuration then constructs an explicit allowlist. Only trusted backend/operator readiness may be supplied; missing or unknown readiness is unavailable. Config intent alone cannot enable providers/features. Unimplemented policy routes are null. Public DTOs exclude operator budget settings, endpoint URLs, key references, user identifiers and diagnostics. The Worker implements unauthenticated `GET /api/public-config` with a strict static allowlist for this increment: the example is available and all live capabilities are unavailable. Actual Pages-to-Worker response/no-store behavior is covered by a workerd test. Operator-configured runtime integration remains later work.

The reviewed currency/date primitives are shared with core. Start/disclosure use the same supported currency subset and valid IANA timezone rules. Authenticated onboarding requires `exampleData=false` and does not equate readiness with already accepted consent. Purchase display money remains integer strings or null; actual totals derive from the core kernel.
