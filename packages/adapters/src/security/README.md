# Credential and connection OAuth foundation (T06)

Worker callers must construct `createCredentialCipher` from a versioned platform-secret keyring when integrating these ports. Production keys belong in Cloudflare secrets; tests use explicitly synthetic disposable values. Each base64url key decodes to exactly 32 bytes. The active key alone encrypts; retained older versions decrypt during controlled rotation. AES-256-GCM uses a fresh native Web Crypto 12-byte random nonce, 128-bit tag and deterministic JSON-tuple AAD containing schema version, trusted tenant ID, entity ID, purpose and encryption-key version. This protects storage, not operator access or end-to-end confidentiality.

Purpose-bound payloads are limited to mailbox/storage token fields, a BYOK key, or a PKCE verifier. Unknown fields, oversized values and invalid versions are rejected. Plaintext is bounded by UTF-8 bytes before encryption, consistently with the decryption limit. Envelopes contain only schema version, key version, nonce and authenticated ciphertext; malformed envelopes, swaps and tampering fail with redacted codes.

`createCredentialVault(db, cipher)` accepts opaque core TenantContext and a target connection ID/current generation or the single BYOK settings ID `primary`. `save`, `refresh`, `rotate` and `clear` take an expected credential version. These writes check the active profile, generation and record version atomically; older configured key versions cannot downgrade newer stored ciphertext. Connection refresh and reconnect save preserve an omitted refresh token. Explicit clear removes ciphertext/key-version fields, increments credential version and generation, and disables the connection schedule or marks the BYOK row deleted. A deleted BYOK row is a retained barrier, not implicitly recreated by a stale save; explicit reactivation is deferred to T11. `read` is for trusted internal processing only, never settings/export/browser responses, and checks the row again after asynchronous decryption. `metadata` returns only configured/version/key-version/generation fields. Unexpected driver errors are mapped to fresh safe CredentialError values without retaining original message, stack, cause, SQL or payload.

`createOAuthStateStore(db, cipher, {callbacks, clock})` is for independent mailbox/storage authorization. The callback registry is server configured, purpose/provider keyed and exact HTTPS; requests cannot override destinations. Creating state requires a verified session-authority TenantContext and a live session belonging to that user. State and nonce are independently random 32-byte base64url values. D1 retains only SHA-256 state, initiating user/session/purpose/provider/fixed callback, encrypted PKCE, nonce and a maximum ten-minute lifetime. Callback consumption checks every binding, current profile/session/expiry, decrypts PKCE, then atomically compares the original ciphertext/key-version/nonce and all current bindings before clearing PKCE/nonce and marking consumed. Only one caller receives the verifier. Wrong bindings leave a legitimate state unconsumed. Tenant-scoped expiry purge is bounded to 100 rows. PKCE supplied to this port must come from trusted connector code, not a public request field. App-login state remains the pinned auth library's separate responsibility.

Migration `0004_credentials_and_oauth.sql` adds connection credential CAS version with paired ciphertext/key-version integrity, a single stable encrypted BYOK credential row per user, composite session ownership and indexed bounded OAuth-state retention. A populated upgrade preserves valid encrypted credentials; invalid legacy ciphertext/key-version pairs fail closed without rewriting data. AI destination/model/mode configuration is deferred to T11; saving a key here does not select an inference destination. No provider-specific SDK type crosses core boundaries, and no network request, custom provider endpoint, cost, secret creation, live OAuth, provider revocation or deployment is performed by these helpers.

Future T05/T08 callers derive context/session ID from verified authority and enforce origin/recent-authentication rules for sensitive mutations. T07/T08 must serialize external token refresh before calling a provider and recheck generation before external effects: persistence CAS alone cannot make two simultaneous provider refresh requests safe. A request already submitted before clear may finish; these helpers do not claim remote cancellation. T11 must enforce destination/consent revisions and write-only settings DTOs. T15 supplies complete disconnect/account deletion and recovery reconciliation. Login, mailbox permission, processing authorization and archive permission remain separate.
