# T18 folder and explicit backfill persistence proposal

Status: read-only design handoff, not implemented or independently runtime-certified. Author: database specialist. Writable scope was this report only. No migration, source, test, configuration, provider request or native command was changed/executed for this assignment.

## Inspected baseline and decision

Inspected migration 0018, core `archive/objects.ts`, adapter `drive/objects.ts`, `drive/types.ts`, Drive service/refresh seams, migration 0002 documents/source schema, current lifecycle `m1-leaf-cleanup.ts`, docs 02/03/04, canonical scope/security/collaboration rules, task T18 and DRIVE-01–06/LATE-DRIVE-01–02 cases. Inspection commands (`cat`, `sed`, `rg`) only; two exploratory searches referenced nonexistent paths and reported that explicitly before corrected paths were read. Parent reports current archive-object native verification; this specialist did not execute it. Parent also confirms earlier consent tests are verified, superseding the historical pending-consent note.

Recommend migration 0019 with three narrow tables: one root-folder plan per storage identity, one explicit backfill run, and its bounded frozen document membership. No new generic job engine, raw bytes, folder hierarchy, R2, provider fetch, resumable session or financial write belongs to this persistence slice. Root-only folder meets docs04; year/month folders are optional and deferred.

Two material baseline constraints require explicit handling:

1. `archive_objects` has UNIQUE(user_id,document_id,storage_connection_id), and request() only returns a row matching current settings_version. Disable/re-enable produces a new settings version: the old pending row occupies the key and cannot currently be requested. Adding settings version to the key would permit duplicate originals and is rejected. Introduce explicit guarded pending-work reauthorization described below; retain immutable plans.
2. `documents` has neither insertion time nor monotonic discovery sequence. received_at/document_date measure mail/event dates, not membership at user action. Random IDs and SQLite rowids are not immutable discovery watermarks. A cutoff-only query could admit subsequently discovered old mail or reused rowids. Freeze a bounded membership set atomically instead of claiming a full historical snapshot from those columns.

## Proposed exact migration 0019 contract

All integer counters/timestamps have typeof(integer), nonnegative and MAX_SAFE_INTEGER checks; revision counters use the existing 2147483646 maximum. Text IDs use existing bounded identifier rules. Every association uses composite owner foreign keys. No arbitrary JSON payload column.

**archive_folders**: user_id, connection_id, storage_subject, planned_file_id, workspace_marker, state ('planned'|'ready'), verified_at nullable, lease_id nullable, lease_expires_at default0, fence default0. Primary key(user_id,connection_id); FK(user_id,connection_id) -> connections(user_id,id), RESTRICT. Planned ID and marker are non-null, immutable once inserted; allowed ID/marker shapes match Drive transport. state ready requires verified_at non-null; planned requires it null. Lease pairing/fence rules match archive_objects. Index only if measured dispatcher needs it; single-identity lookup uses PK. No access token, credential version, folder title from invoice text or raw response persisted.

The folder belongs to a verified provider subject, not a consent revision or access-token lifetime. Current generation/settings version are supplied to every operation and checked against live connection/settings; a same-subject new generation may reuse the same planned folder only after explicit current archive consent and remote metadata verification. Do not auto-replace its ID when the folder is remotely missing: report recovery required, preserving ambiguous-result reconciliation. Subject mismatch fails closed; no cross-account reuse.

**archive_backfill_runs**: id, user_id, connection_id, storage_generation, storage_subject, settings_version, created_at, cutoff_document_id nullable, snapshot_count (0..100), cursor_ordinal (0..100), state ('pending'|'completed'|'cancelled'), revision default1, lease_id/lease_expires_at/fence with existing lease rules. Primary key(user_id,id), globally unique id for opaque queue references; FK(user_id,connection_id) -> connections(user_id,id), RESTRICT. Unique partial index(user_id) WHERE state='pending' prevents multiple competing workspace backfills. Snapshot/cursor integer invariants, terminal rows have no lease. Index(user_id,state,lease_expires_at,id) for bounded tenant dispatch. cutoff_document_id is the last selected immutable ID for disclosure/resumption of a later explicit selection; it is NOT sufficient membership authority.

**archive_backfill_items**: user_id, run_id, ordinal (1..100), document_id. Primary key(user_id,run_id,ordinal), UNIQUE(user_id,run_id,document_id); FK(user_id,run_id) -> archive_backfill_runs(user_id,id) CASCADE; FK(user_id,document_id) -> documents(user_id,id) CASCADE. This table freezes identities only, never source bytes. Deleted documents remove items; ordinal gaps must be supported and must not be reported as successful archives. Existing document owner PK supports frozen selection; indexed item ordinal supports each page.

Proposed fixed initial bound: each explicit action snapshots at most 100 existing document records, in ID order, from the workspace or a server-validated selected mailbox. Read at most 101 candidate IDs to disclose more records, filter current eligibility afterward, and freeze the first 100 (including presently unavailable sources). Do not scan an arbitrarily large sparse eligible set looking for 100 accessible originals. Root must approve this deliberately bounded product scope: it is not automatic full-history archiving. A later explicit action may request the next bounded range; inputs remain document/mailbox selection bounds, never arbitrary URLs or authority IDs. created_at is action time; immutable item membership is the actual cutoff. Documents inserted afterward cannot enter the run regardless of their dates/IDs.

## Narrow repository interfaces and guards

Suggested core ports, trusted TenantContext first throughout:

- Folder: `getOrPlan(context,{connectionId,settingsVersion,expectedGeneration,proposedFileId,workspaceMarker}) -> stored plan`; proposed remote ID comes only from trusted transport generateIds. INSERT-if-absent plus read returns the winner on concurrent documents; losing generated IDs are unused, not remotely created. Callers MUST use returned stored ID. `claimFolder(...) -> lease|busy`, `folderAuthorized(context,lease,authorizationSnapshot) -> boolean`, `completeFolder(context,lease,authorizationSnapshot) -> boolean` after real ensureFolder verifies metadata. No create HTTP before committed plan. Ready folders are inspected when used; rename/move alone does not choose another ID.
- Backfill: `startBackfill(session,{settingsVersion,connectionId,expectedGeneration,afterDocumentId?}) -> run metadata`; active/recent actual DB session and explicit request required, no enable callback calls this. `claimBackfill(context,runId)`, `admitPage(context,lease,{expectedCursorOrdinal,expectedRevision}) -> {admitted,unavailable,alreadyArchived,nextCursor,done}` with server page bound initially five items. No caller-provided document list/cursor truth. Completion of enumeration means admitted, not uploaded.
- Objects: add `reauthorizePending(context,{documentId,storageConnectionId,settingsVersion,expectedGeneration,expectedObjectFence})`. Bind actual owned unchanged document/source tuple, live mailbox identity/generation, storage subject, enabled current archive_settings and active profile. Preserve file/parent/hash/MIME/size tuple, clear prior lease and increase fence so late workers cannot complete. Only same-source/same-storage identity pending work can rebind; mismatched immutable evidence requires explicit conflict, not overwrite. An already archived row is read as historical successful metadata and never reset/uploaded again. Return distinction `already-archived` versus `admitted`; do not claim a current remote availability check occurred.

Every actual SQL mutation repeats full live authority and lease predicates. Bind current storage subject/generation, source availability/mailbox generation, enabled accepted settings version, active profile and absence of current connection-erasure work. Keep credential-version checks at credential acquisition/send: token refresh increments credential_version without changing storage identity; pinning an object forever to the old credential version would incorrectly strand it. After any refresh, reread current credentials and repeat authority immediately before outbound requests. The supplied authorization snapshot cannot be authority by itself. A DB guard cannot eliminate a revoke-after-check network race; submitted requests may finish, but post-network commit must fail without resurrecting metadata.

## Atomic admission and native statement budget

Start in one batch: conditional run insertion plus bounded item INSERT SELECT with the same live/session/consent snapshot; populate count/cutoff from actual inserted items under run token. Treat zero winning run mutation as conflict. No partial run on later SQL failure. Avoid simply letting all batch statements no-op then claiming success; verify the winner/read guarded committed run.

For each leased page: select up to five frozen ordinals after cursor, joining actual owned documents/sources/mailbox/storage; categorize without reading bytes. One set-based guarded INSERT SELECT admits new archive_objects; one guarded update handles only explicit safe pending reauthorization (preserves plans/increments object fences); one conditional run cursor CAS commits the exact page upper ordinal/revision, with outcome counts from database rows. All statements bind the same run lease/fence/live snapshot. If stale cursor/lease/profile/settings is detected, rollback admission rather than leaving records created while the cursor reports failure; prove a conditional abort/sentinel guard using actual D1 batch semantics. A later provider failure does not rewind admission. Crash after commit replays the same durable work identities. No available original is asserted from DB available=1 alone: remote retrieval may later reveal deletion.

Target admission cost: page read1 + guard/abort1 + insert1 + reauthorization1 + cursor1 + result1 = at most6 native statements, independent of page width. Folder plan miss insert+read2; claim1; pre-send authority1; post-network commit1. Do not call existing request() twice per document in a loop (five items already consume10 statements plus repeated guards). Reserve shared40 counter headroom for session/vault refresh, source fetch checkpoint and final settlement; reaching budget fails before HTTP or retries durable work. Exact whole invocation <=40 must be measured with real composition, not inferred from these targets. No Free-plan CPU/row-scan viability claim.

## Lifecycle and retention integration required before activation

Existing prepass inventories seven fixed leaf tables, drains at most100 rows/unit, preserves legacy integer stages and skips expensive connection recompute stage9. Adding two run/folder parents with CASCADE item deletion could exceed100 mutations. Add items FIRST to inventory, then run, then folder; both account and matching storage-connection deletion must drain items before run parents. Item predicate joins owned run.connection_id (items have no connection_id); when mailbox disconnect deletes documents, explicitly drain affected items before document cascades too. Keep old stage numbers and current request/profile/journal guards; outer1+inventory1+candidate1+delete1 remains4 statements, empty leaf+old path remains<=5. Test item/run cleanup order and resumed mid-stage migration compatibility.

Do not cascade folder/run parents in a way that silently erases hundreds of leaves in one unit. Public FX rates remain public; financial values are untouched. Local metadata deletion leaves user-owned remote folders/files untouched. Current0018 cascade erases archive_objects metadata on document/storage deletion: this agrees with current docs03, but cannot promise archive links after source/account erasure. If product requires retained links when originals are removed locally, that is a separate schema/retention decision, not silently added here.
