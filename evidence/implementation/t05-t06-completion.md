## Implemented behavior

The configured Google backend performs allowlisted verified identity login, signed live D1 session lookup, tenant-scoped preferences with optimistic version checks, and logout. It requests only identity scopes and discards provider tokens. A narrow public Better Auth extension verifies signed identity claims and nonce; the library owns PKCE, cookies and one-use login state. Persisted login identifiers are hashed and state values encrypted. Request-local compensation removes only newly created identities with neither account nor session after provisioning failure; the unique provider identity index prevents two workspaces for the same Google subject under concurrent callbacks. Unknown auth routes retain their established 404 behavior. Private routes require a trusted session; unimplemented authenticated operations return explicit unavailable responses.

The internal credential cipher/vault accepts validated versioned server keys, uses AES-256-GCM with tenant/entity/purpose/key-version binding, preserves omitted refresh tokens, rotates through optimistic writes and rejects stale generations. Secret metadata and errors exclude credentials. Connection OAuth state binds a live user/session to a fixed purpose/provider/callback, expires within ten minutes and yields encrypted PKCE to one winning consumer. Clear removes stored ciphertext and fences late writes/reads. These ports are exercised in actual local workerd/D1, but real mailbox and AI callers are future integration tasks.

Shared strict profile/preference schemas generate the checked-in profile OpenAPI document. API responses apply no-store, content-type, framing, referrer and CSP protections. Static Pages headers are declared separately; deployment smoke evidence is still required. Preferences accurately report valuation as not configured while FX jobs remain absent.

The owner's configuration rule is recorded in architecture and agent rules: external services, especially inference/parsing, use provider-neutral application ports; the Worker selects adapters through validated environment/Wrangler variables and supplies server secrets. Hosted and BYOK use the same interfaces, without silently changing the user's approved destination. No AI provider integration is claimed by these foundational tasks.
