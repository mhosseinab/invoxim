# Implementation foundation

T02 established `@invoxim/web` (React/Vite and a thin Pages Function) and `@invoxim/worker` (the modular Worker). Later tasks added shared contracts/core/adapters, persistence, authentication, mailbox processing and AI components. Current implementation status and exact verification evidence are recorded in `.agents/backlog.json` and `evidence/implementation/`; this foundation guide does not certify the whole application or live integrations.

Run `pnpm install --frozen-lockfile --ignore-scripts`, then `pnpm verify`. Dependency lifecycle scripts are disabled by workspace policy. Both app builds are local: Vite and Pages Functions compilation, and Wrangler `deploy --dry-run`. No remote resource identifiers or secrets are configured.

Persistence uses native D1 and the existing shared invocation meter; authentication uses its Drizzle adapter. The single active migration is `packages/adapters/migrations/0001_initial.sql`; historical migrations are compatibility fixtures. The baseline preserves application constraints, indexes and required scheduler seeds. Existing databases require the documented non-destructive transition in `evidence/implementation/baseline-transition-checklist.md`.

Workspace policy disables lifecycle scripts and explicitly denies the reviewed esbuild/workerd versions. Unreviewed dependency builds still fail the strict build policy. No Prisma generation step or custom Prisma driver remains in the application.

For local development, run `pnpm run dev` from the repository root. It starts the existing Vite frontend and local Wrangler Worker together through uncached, persistent Turbo tasks. Vite defaults to `http://localhost:5173` (the example is `/demo`); the Worker defaults to `http://localhost:8787`. Use the addresses printed in the terminal if ports are occupied. Stop both with Ctrl+C. Vite serves the frontend; the production Pages Function/service-binding proxy is verified separately and is not provided by Vite. Auth, Gmail, discovery and jobs retain their disabled defaults.

`verify` runs import boundaries, bounded secret-pattern and dependency-policy checks, Prettier formatting, Biome checks, ESLint, strict types, tooling/workspace unit tests, workerd integration tests, builds and browser E2E. It discovers concrete `packages/*` through pnpm/Turbo. `pnpm test:security` executes an explicit native adversarial suite, including lifecycle account/session isolation and workspace-token purposes; these cases overlap the integration suite. `pnpm check:deps` runs the local dependency policy followed by the registry's plain `pnpm audit --json`; CI requires that audit and the explicit security suite after `verify`. Registry failures and findings are not ignored. `pnpm test:eval:offline` executes the synthetic extraction corpus; `pnpm test:eval:clef` runs the Clef evaluation dry-run (see `clef-eval.md` for opt-in live evaluation). Neither establishes real-model quality. None of these commands alone certifies M0 or release readiness.

`pnpm check:secrets` traverses the filesystem without requiring Git, including untracked source, tests, docs and evidence. It reports bounded relative paths, lines and rule names with matched credential values redacted. It rejects encountered symlinks and exceeded scan bounds; recognized binary assets, named generated/dependency directories and Git history are excluded. Files with fake binary extensions are scanned as text or rejected. Narrow documented synthetic fixture values are allowed, while recognizable vendor/private-key signatures remain findings. Arbitrary, encoded or short credentials and secrets embedded in actual media are outside this pattern check. Local `.env` and `.dev.vars` are included; operator credentials must remain outside the scanned publishable tree. `pnpm check:dependency-policy` checks exact direct versions, workspace links, pinned pnpm and lock integrity metadata offline; frozen install and the separate advisory audit remain required. Scope, exclusions and actual execution evidence are recorded in `evidence/implementation/t16-security-gates.md`.

`pnpm lint:biome` checks the repository, including test files, and fails on warnings. Biome uses its recommended rules and import organization; Prettier remains the formatter and ESLint retains TypeScript-specific checks. CI invokes the same `pnpm verify` gate. The tooling regression suite runs actual Biome against temporary test files with non-null assertions and control-character regexes and checks that verification/CI retain the pinned gate. Workspace editor recommendations and settings live in `.vscode`; an editor extension starting successfully still requires verification in that editor.

The boundary checker parses TypeScript/JavaScript imports, exports, literal dynamic imports, and require calls, detects relative workspace imports and package subpaths, rejects undeclared workspace imports, unknown workspace dependencies, cycles, and prohibited layer relationships. Core/contracts cannot import the identified runtime/provider infrastructure packages. Tests/configuration/generated outputs are excluded from production-import scanning. This is a static dependency guard, not a complete security scanner or universal provider-client detector.

Tests use synthetic data in local workerd. The Pages context uses the plugin's real context constructor and a synthetic Worker service binding to verify transport semantics. Live Pages hosting, providers, authentication, D1, queues and models are not verified by these tests.

For filesystem-restricted agents, set `WRANGLER_LOG_PATH` to a unique approved temporary log file ending in `.log` (for example `/tmp/invoxim-wrangler-check.log`). Turbo passes this and `WRANGLER_SEND_METRICS` through. Use `WRANGLER_SEND_METRICS=false` and `TURBO_TELEMETRY_DISABLED=1` to disable CLI telemetry. Default Wrangler logs may be outside the workspace.

If the default Wrangler service registry is outside permitted writable paths, set `WRANGLER_REGISTRY_PATH=/tmp/invoxim-dev-registry` when running `pnpm run dev`. Turbo forwards that supported Wrangler override too.

Context7 was unavailable. Exact plugin exports/types and CLI behavior were checked locally; official dependency documentation and immutable CI action tag revisions are recorded in T02 evidence. CI has read-only contents permissions, disables checkout credential persistence, runs frozen no-script installs and foundation verification on Ubuntu 24.04, and contains no deployment/secrets step.
