# T18 archive workflow design handoff

This is a proposed implementation design returned by independent read-only specialist `/root/discovery_review`, not a completion or implementation approval. The reviewer inspected existing transport/original/job/lifecycle code and specification files before migrations 0017/0018 existed. Root records this handoff after 0017 was authored; no review of that migration is inferred.

The existing job store requires mailbox processing consent. Substituting a storage connection would violate its guards. The recommended small design is a separately fenced durable archive work item, dispatched through the existing queue, binding both source mailbox generation and explicit storage settings version/generation. It should reserve settlement capacity within the shared invocation SQL budget.

Persist a planned folder/file ID before each remote create. Claim/checkpoint/finish require tenant ownership, active profile, current source and storage authority, and increasing fences. Persist only source identity and immutable MIME/hash/size tuple; reread exact bytes transiently for retries. Lost response, 409 or failed local commit must inspect and reuse the same remote ID. Verify owner, parent, marker, digest and size before marking archived. Disabling/disconnecting/deleting may leave an already submitted remote upload but cannot allow subsequent requests or resurrect local rows.

Migration 0018 remains reserved for actual archive objects/folder plans/work leases and bounded backfill cursors. Composite tenant foreign keys and retention behavior must be reviewed against connection erasure, preserving valid archived-original access and user-owned Drive files. No archive-plan implementation is approved here.

Resumable upload needs its own validated original-byte policy; do not silently inherit the extraction byte cap as arbitrary-size support. Bound chunks and rereads, encrypt/validate the upload-session URI, respect approved upload origin/path and reject redirects. Progress must use the server's verified acknowledged range; expired sessions reuse the persisted file plan after reconciliation. Above-policy inputs remain explicitly unsupported without truncation. See Google's primary upload guide: https://developers.google.com/workspace/drive/api/guides/manage-uploads.

Required future tests include durable-ID-before-upload, concurrent plan/lease claims, all lost-response/409/failed-commit paths, wrong metadata/digest/parent/owner, revoked credentials/quota/folder failure, disable/delete at each network boundary, expired resumable session/range ambiguity/source changes, exact MIME and attachments, bounded explicit backfill with crash recovery, tenant denial, lifecycle leaf erasure and measured combined SQL budget. These are proposed tests; they have not executed as archive workflow acceptance evidence.
