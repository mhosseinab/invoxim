# Implementation foundation

T02 established `@invoxim/web` (React/Vite and a thin Pages Function) and `@invoxim/worker` (the modular Worker). Later tasks added shared contracts/core/adapters, persistence, authentication, mailbox processing and AI components. Current implementation status and exact verification evidence are recorded in `.agents/backlog.json` and in evidence records kept outside git (historical copies are in the commit history before fe99887); this foundation guide does not certify the whole application or live integrations.

Run `pnpm install --frozen-lockfile --ignore-scripts`, then `pnpm verify`. Dependency lifecycle scripts are disabled by workspace policy. Both app builds are local: Vite and Pages Functions compilation, and Wrangler `deploy --dry-run`. `apps/worker/wrangler.jsonc` names the production D1 database, Queues and OAuth client IDs, but the dry-run uploads nothing and no secret values are committed.

Persistence uses native D1 and the existing shared invocation meter; authentication uses its Drizzle adapter. `packages/adapters/migrations/0001_initial.sql` is the consolidated baseline, followed by incremental migrations `0002` through `0007`; the former migration sequence is kept only as compatibility fixtures in `apps/worker/test/migrations/historical/`. The baseline preserves application constraints, indexes and required scheduler seeds. Existing databases require the documented non-destructive transition in `docs/runbooks/baseline-transition-checklist.md`.

Workspace policy disables lifecycle scripts and explicitly denies the reviewed esbuild/workerd versions. Unreviewed dependency builds still fail the strict build policy. No Prisma generation step or custom Prisma driver remains in the application.

For local development, run `pnpm run dev` from the repository root. It starts the existing Vite frontend and local Wrangler Worker together through uncached, persistent Turbo tasks. Vite defaults to `http://localhost:5173` (the example is `/demo`); the Worker defaults to `http://localhost:8787`. Use the addresses printed in the terminal if ports are occupied. Stop both with Ctrl+C. Vite serves the frontend; the production Pages Function/service-binding proxy is verified separately and is not provided by Vite. `wrangler dev --local` reads the checked-in `wrangler.jsonc` variables (which enable auth, Gmail, discovery, extraction, jobs and corrections) against local D1 and Queue simulations. Features that need server secrets stay unavailable unless you supply them in an untracked `.dev.vars`, and the local database is empty until you apply migrations with `--local`.

`verify` runs import boundaries, bounded secret-pattern and dependency-policy checks, Prettier formatting, Biome checks, strict types, tooling/workspace unit tests, workerd integration tests, builds and browser E2E. The tooling tests (`node --test tools/implementation/*.test.mjs`, the first half of `pnpm test:unit`) include two documentation checks: `documented-scripts.test.mjs` fails when a `pnpm` script shown in a code span or block in `README.md` or `docs/*.md` is missing from the root or named package's `package.json`, and `doc-paths.test.mjs` fails when a tracked Markdown file outside `.agents/` cites a missing `docs/` or `evidence/` path (the refactor plan's historical appendix and the turbo-managed block in `AGENTS.md` are skipped). It discovers concrete `packages/*` through pnpm/Turbo. `pnpm test:security` executes an explicit native adversarial suite, including lifecycle account/session isolation and workspace-token purposes; these cases overlap the integration suite. `pnpm check:deps` runs the local dependency policy followed by the registry's plain `pnpm audit --json`. CI runs each gate once: `verify` already covers the dependency policy and the security suite (via `test:integration`), so CI adds only `pnpm audit --json` afterward. Registry failures and findings are not ignored. `pnpm test:eval:offline` executes the synthetic extraction corpus; `pnpm test:eval:clef` runs the Clef evaluation dry-run (see `clef-eval.md` for opt-in live evaluation). Neither establishes real-model quality. None of these commands alone certifies M0 or release readiness.

`pnpm check:secrets` traverses the filesystem without requiring Git, including untracked source, tests, docs and evidence. It reports bounded relative paths, lines and rule names with matched credential values redacted. It rejects encountered symlinks and exceeded scan bounds; recognized binary assets, Git history, directories named `.git`, `.pnpm-store`, `node_modules`, `.turbo`, `.wrangler`, `.worktrees`, `dist`, `.production` (generated build graphs, checked by `pnpm check:production`), `coverage`, `playwright-report`, `test-results` or `__pycache__`, and the root-relative `.claude/worktrees` (other agents' checkouts) are excluded. Files with fake binary extensions are scanned as text or rejected. Assignment findings whose values start with `synthetic-`, `qa-` or `fake-` are allowed only in fixture locations (test/spec files, `*.example`, `testkit/`, `evidence/implementation/` at any depth, `spikes/` and `apps/worker/test/onboarding-qa-fixture.ts`), while recognizable vendor/private-key signatures remain findings everywhere. Arbitrary, encoded or short credentials and secrets embedded in actual media are outside this pattern check. Local `.env` and `.dev.vars` are included; operator credentials must remain outside the scanned publishable tree. `pnpm check:dependency-policy` checks exact direct versions, workspace links, pinned pnpm and lock integrity metadata offline; frozen install and the separate advisory audit remain required. The original T16 scope and execution evidence are in the evidence record `t16-security-gates.md` (kept outside git; it was never committed).

`pnpm lint:biome` (also `pnpm lint`) checks the repository, including test files, and fails on warnings; it honors `.gitignore`, so ignored output such as `evidence/implementation/` is not linted. There is no ESLint. Biome uses its recommended rules and import organization; Prettier remains the formatter over a derived file set (`.prettierignore` excludes prose, agent, and design fixtures), not a hand-maintained path list. Package boundaries are enforced by `check-boundaries.mjs`, not a lint rule. CI invokes the same `pnpm verify` gate. The tooling regression suite runs actual Biome against temporary test files with non-null assertions and control-character regexes, checks that verification/CI retain the pinned gate, and pins the semantic deploy contract in `deploy-workflow.test.mjs` (reused verification gate, production approval environment, immutable action revisions, main-reachable deploys, resource names only from wrangler.jsonc, no remote migration or secret change, Worker before Pages). Workspace editor recommendations and settings live in `.vscode`; an editor extension starting successfully still requires verification in that editor.

The boundary checker parses TypeScript/JavaScript imports, exports, import types, import-equals, literal dynamic imports, and require calls; a nonliteral dynamic import fails the check. It rejects relative imports that cross into another workspace package (they must use that package's root name), `@invoxim/<pkg>/<subpath>` imports, relative code imports that resolve outside every package (repository-root JSON such as `contracts/` and `config/` is allowed), undeclared workspace imports, unknown workspace dependencies, cycles, and prohibited layer relationships. Declared `devDependencies` count toward the layer graph. Allowed layers are: web → contracts, core; worker → core, adapters, contracts; adapters → core, contracts; core → contracts; testkit → core, contracts; no layer may depend on testkit. Core/contracts cannot import the identified runtime/provider infrastructure packages. `test`, `tests` and `__tests__` directories, `*.test.*`/`*.spec.*`/`*.config.*` files, and `node_modules`, `dist`, `.wrangler` and `.turbo` are excluded from scanning. This is a static dependency guard, not a complete security scanner or universal provider-client detector. Built bundles are checked separately by `production-artifacts.mjs` (`pnpm check:production`, run by `pnpm build`), which rejects test/debug packages, including `@invoxim/testkit` and any `packages/testkit/` module input.

Tests use synthetic data in local workerd. The Pages context uses the plugin's real context constructor and a synthetic Worker service binding to verify transport semantics. Live Pages hosting, providers, authentication, D1, queues and models are not verified by these tests.

For filesystem-restricted agents, set `WRANGLER_LOG_PATH` to a unique approved temporary log file ending in `.log` (for example `/tmp/invoxim-wrangler-check.log`). Turbo passes this and `WRANGLER_SEND_METRICS` through. Use `WRANGLER_SEND_METRICS=false` and `TURBO_TELEMETRY_DISABLED=1` to disable CLI telemetry. Default Wrangler logs may be outside the workspace.

If the default Wrangler service registry is outside permitted writable paths, set `WRANGLER_REGISTRY_PATH=/tmp/invoxim-dev-registry` when running `pnpm run dev`. Turbo forwards that supported Wrangler override too.

Context7 was unavailable. Exact plugin exports/types and CLI behavior were checked locally; official dependency documentation and immutable CI action tag revisions are recorded in T02 evidence. Foundation verification (`.github/workflows/verify.yml`) has read-only contents permissions, disables checkout credential persistence, runs frozen no-script installs and foundation verification on Ubuntu 24.04, and contains no deployment/secrets step. Deployment automation is separate: `.github/workflows/semantic-deploy.yml` reuses that gate, then deploys the Worker and the Pages frontend behind an owner-approval environment and Cloudflare credentials. It deploys only main-reachable commits (from a `v*.*.*` tag or a manual dispatch), reports pending D1 migrations read-only, and performs no migration, secret or release-gate change; for a manual dispatch the approval reviewer must confirm the run's ref and commit before approving, as `docs/09-operations-and-costs.md` states. Cloudflare resource names come only from the checked-in `apps/*/wrangler.jsonc` files; Pages deploys with `--branch main`, which must be the project's production branch.
