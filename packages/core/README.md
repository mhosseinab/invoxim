# Exact domain kernel

Pure portable arithmetic; no infrastructure, persistence, mailbox access or inference. `@invoxim/core` exports source TypeScript for consumer bundlers. Build checks types without emitting an independent bundle.

`parseMoney` validates currency precision and the per-entry magnitude bound of 9,000,000,000,000 minor units. Unknown amounts remain null. `formatMinor` produces exact decimal text without locale grouping. `ledgerTotals` takes already accepted payment/refund magnitudes and eligibility, validates dates/currency/bounds, and returns integer strings. A period is start-inclusive/end-exclusive. Mixed currencies require explicit per-entry valuation elsewhere; no rate-one fallback. These pure reductions do not deduplicate event identities: future persistence/reconciliation must enforce idempotency before supplying accepted entries.

`planLedgerIngestion` is the production rule that turns extracted purchase facts into planned cash events. An unpaid invoice is not spending. Cash events use payment/refund magnitudes, never the document total, and keep the printed calendar date. Unknown payment state and missing totals stay in review. A credit note, even one that reports a completed cash refund, stays in review for later reconciliation; its label alone never creates a refund. The planner returns a plan only; persistence and idempotency belong to the adapters.

`convertMinor` uses positive exact decimal rates and half-away-from-zero rounding per signed entry. `convertFxEntry` values one ledger entry against a supplied historical quote snapshot. A missing, mismatched, future-dated or older-than-`maxPriorAgeDays` quote (`fxRateAgeDays`) leaves the entry unconverted with an explicit reason; there is no rate-one fallback. `sumFxConversions` sums already-rounded valuations. `monthlyAnchor` clamps a month-end anchor without losing its original day. `deriveRecurringSuggestion` produces annual estimates and price comparisons as suggestions only; they never create ledger events.

Supported currencies are the reviewed SIX subset EUR/USD/GBP/CHF (2 digits), JPY (0), KWD (3), published 2026-09-17. Other ISO currencies fail closed until independently reviewed. The reference and hash were recorded in the T03 currency-reference evidence file, which is no longer in the tree (removed in fe99887; see Git history). No live rates or provider connections are supplied.
